# After install: what the kit wrote, why, and how it maintains itself

Reference for an installed kit. For the pitch, see the [README](../README.md); for install routes,
[install.md](install.md); for the guard list, [hooks.md](hooks.md); for turning levels, groups or
single hooks on and off, the [Change the setup later](install.md#change-the-setup-later) section.

## Where your choices are stored

The `agent-tiers` CLI and `/agent-tiers:setup` (flat route: `/agent-tiers-setup`) keep every
choice in one file, the profile's `settings.json` (`~/.claude/settings.json`, or
`$CLAUDE_CONFIG_DIR/settings.json`). Each run that changes it first writes a timestamped `settings.json.bak-*` next to it and keeps the
newest 5.

| What | Where in `settings.json` |
|---|---|
| `enabled`, `group_<name>`, `disabled_hooks` | `pluginConfigs["agent-tiers@agent-tiers"].options`, on both routes (the plugin's options in `/config` edit the same entry; `disabled_hooks` is not shown there) |
| `AGENT_TIERS_NOTIFY_TERMINAL`, `AGENT_TIERS_NOTIFY_FOCUS_CMD`, `AGENT_TIERS_BADGE_GLYPHS` | `env` |
| `statusLine`, `subagentStatusLine` (only when the status line extra was accepted) | Top level, pointing at the kit's `scripts/statusline.sh` and `scripts/statusline-subagent.sh` |
| Flat route only: the kit's hook rows | `hooks`, written by `install-flat.sh` |

On the flat route, `install-flat.sh` also records the hook rows it owns in the kit's own
`.state/integrations.json` (a per-profile file for a second profile). A level is not stored: it
only sets the `group_<name>` options, and `sh ~/.claude/agent-tiers/scripts/agent-tiers status`
reads them back.

## Per-project artifacts (generated by `/agent-tiers:init`)

- `.claude/agent-tiers.local.md` - the recorded model/effort **resolution** for this environment.
- An auto-memory copy of the same facts (always loaded, survives `/compact`).
- `.claude/skills/tier-project-brief/SKILL.md` (L2) - your build/test/verify + landmines, hooked by every
  tier; plus any prefixed L3 task agents you opt into. `.claude/agent-memory-local/` git-ignored.
- A `## Agent tiers` + `## Building` + `## Workflow essentials` block in the project `CLAUDE.md` (idempotent
  - re-run to update it), and a `RESUME_SESSION.md` handoff.
- (Optional, offered) a **CLAUDE.md layout review** - scaffold/slim the project file toward the recommended
  shape (`context-file-layout` skill + `templates/CLAUDE.project.example.md`); never touches your personal global file.

## Extras (optional)

Extras are the `extra` rows in `install/options.tsv`. The CLI only proposes them; nothing is written
without a yes.

- **Status line** (`statusline`): sets `statusLine` and `subagentStatusLine` in `settings.json` to the
  kit's `scripts/statusline.sh` and `scripts/statusline-subagent.sh` (folder, model, git branch,
  context use, session time). Needs `jq`; without it the scripts print nothing. Icons are plain ASCII;
  set `AGENT_TIERS_BADGE_GLYPHS=nerd` for Nerd Font icons.
  - On: `sh ~/.claude/agent-tiers/scripts/agent-tiers configure --set extra_statusline=true`
  - Off: the same with `extra_statusline=false`. Each key is deleted only while it still runs this kit
    copy's script; a different value is left in place. `remove` follows the same rule.
  - On the plugin route, run the same `configure --set ...` through `/agent-tiers:setup configure`, or from any kit checkout's `scripts/agent-tiers`. The command string then points at that checkout, so off and `remove` only recognise it when run from the same checkout.
  - The command holds the kit's absolute path, so moving the kit or a plugin version change leaves a
    stale path. Re-run the `--set extra_statusline=true` command after either.
- **agentsview** (`agentsview`): a session ledger and search tool. The kit does not install it and writes
  nothing for it; `install` prints a pointer. Get the binary from https://github.com/kenn-io/agentsview,
  then run `claude mcp add --scope user agentsview -- agentsview mcp`. Its search index is built with
  `agentsview embeddings build`; schedule that yourself if you want it kept fresh (a systemd user timer
  or cron). The kit ships no schedule.

## Reach-guard allowlist

reach-guard asks before an agent drives a browser, runs a remote shell or cloud CLI, or calls the
GitHub API. Answering Yes on its prompt lasts at most for the session (for a browser, that site and
level; for a read-only Bash command, that group and target); the prompt says which. Your host's
"don't ask again" does not stop reach-guard asking. To make an answer stick, run the line the prompt
labels `POLICY CHANGE` yourself, as a `!` command in Claude Code or in a terminal:
`printf '<group>\t<target>\t<read|all>\n' >> ~/.claude/reach-guard/allow.tsv` (the prompt adds
`mkdir -p` first while that directory is missing, and uses `$CLAUDE_CONFIG_DIR` in place of `~/.claude`
when that is set). Nothing else writes the file, and agents are denied writing it. `agent-tiers reach list` shows the rows; to undo one, delete its line from `allow.tsv` in an
editor. `all` on `remote_shell` lets agents run any plain remote command on matching hosts without
asking; `all` on `cloud` or `gh_api` lets them run that group's act calls (writes, deletes, deploys)
against matching targets without asking. A line labelled `RUN` is a one-off command handed back for you
to run, and changes nothing that persists.

## Why a probe?

How a sub-agent's `model:`/`effort:` frontmatter resolves against the inherited env is **GUI-specific**.
Bash can read effort + the inherited model env, but a sub-agent **cannot introspect its own live model** -
only the GUI's agent/model panel is ground truth. So `/agent-tiers:init` auto-detects what it can and
asks you to confirm the model from your panel once, then records the result.

## Lifecycle: how the kit self-manages

Artifacts drift and bloat, so the kit tracks agent staleness, curates itself (gated, never
auto-deletes), reads a VCS policy for what's personal vs shared, keeps private planning docs out of
tracked history, and graduates recurring patterns from project-local to global.

- **Staleness:** every agent carries a `def-version: N` stamp quoted in its check-in - editing an agent is
  PENDING-REFRESH until a spawn's check-in shows the new number (the host watcher can lag minutes).
- **Curate:** `/agent-tiers:doctor` reports lifecycle thresholds (memory/RESUME/brief/plans sizes, stale
  facts); `/agent-tiers:gc` is the gated fixer (retire/merge/archive/dedup - never auto-deletes, never
  touches your personal `CLAUDE.md`). The SessionStart hook nudges you with a one-line advisory when a
  threshold is breached, on any session start. The `MEMORY.md` check fires in every project; the
  RESUME/brief/plans checks need a `RESUME_SESSION.md` (a project with no handoff file gets no line
  for them).
- **VCS policy:** `kit-config.md` holds your global defaults (commit / ignore-shared / ignore-personal per
  artifact class) if present, else kit defaults apply; `init` offers a per-project override and records it
  in `.claude/agent-tiers.local.md`.
- **Private notes seam:** keep private planning docs in a git-ignored `docs/_local/` mirrored to a side
  `local/notes` ref that is **never merged into a code branch**, so they can't bleed into tracked history.
  `notes-sync.sh` (via `/agent-tiers:notes`) syncs it from any branch without touching HEAD/index; push
  policy is per-project (`local` = never leaves the machine, the default; or a remote name). Convert an
  existing project with the runbook in [private-notes.md](private-notes.md).
- **Promote:** a pattern that recurs in a 2nd project graduates from project files to a kit template/global
  agent (superset); a fact true in any repo graduates to global memory.

## Second Claude account (CLAUDE_CONFIG_DIR)

Claude Code treats that variable as the whole config root - with it set, the CLI builds `.claude.json`,
`projects/` and `sessions/` there and starts **logged out**, which is what makes two accounts work side
by side. ONE kit serves every profile: keep it where it is (`~/.claude/agent-tiers/`) and run the
CLI with the variable set:

```bash
CLAUDE_CONFIG_DIR=~/.claude-work sh ~/.claude/agent-tiers/scripts/agent-tiers install
```

On the flat route the whole flattened view (skills, agents, commands AND `settings.json`) lands in
that profile, with absolute symlinks back to the shared kit and its own integrations ledger. Every
later `configure`, `status` or `remove` for that profile needs the same variable set. Of what the flat install creates outside the kit checkout, one thing is shared
by every profile: `~/bin/agent-tiers-share`. Removing one profile deletes it, so re-run
`install-flat.sh` in a profile you keep to restore it (the checkout's own `kit-config.md` and
`.state/` are shared too). Do NOT copy
the kit into each profile; the tools resolve it from their own location, not from the config dir.

## Per-install settings (environment)

Hooks read these from their environment, so set them in the `env` block of the Claude Code
`settings.json` the kit is installed into (one per profile). Three of them, the notification and
badge keys, can be set through the CLI instead
(`sh ~/.claude/agent-tiers/scripts/agent-tiers configure --set AGENT_TIERS_NOTIFY_TERMINAL=kitty`),
and `install` and `configure` propose values for them from
`scripts/detect-env.sh`, writing none without a yes. The rest go into `env` by hand.
`AGENT_TIERS_SHARE_REMOTE` is the exception: `agent-tiers-share` runs from your own terminal, so
export it there. Unset means the
default; the one default that is new is the `XDG_RUNTIME_DIR` fallback for `PEER_GUARD_SOCK_DIR`, used
only when `/run/user/<uid>/cc-socks` does not exist.

| Variable | Default | Effect |
|---|---|---|
| `AGENT_TIERS_PROTECTED_BRANCHES` | empty | Extra branch names (space-separated, no patterns) that a force-push may never target. A name also matches as the last path part of a ref, so `release` protects `feature/release` too. `main` and `master` are always protected, and so is origin's default branch as recorded locally (`git remote set-head origin -a` records it; `git clone` does it for you). This list only adds to them. |
| `AGENT_TIERS_NOTIFY_TERMINAL` | `alacritty` | Process name (`/proc/<pid>/comm`, at most 15 characters) of the terminal whose window a notification click focuses. |
| `AGENT_TIERS_NOTIFY_FOCUS_CMD` | `i3-msg "[id=%s] focus"` | Command run on a notification click, the first `%s` is replaced by the X11 window id and the result runs through `sh -c`. Its first word must be the command. Empty = no click action. |
| `AGENT_TIERS_BADGE_GLYPHS` | empty | `nerd` adds Nerd Font icons to the operator-tag badges (a warning triangle, a check) and to the status line extra's icons. Without a Nerd Font those render as empty boxes, so the default is plain text and colour. |
| `PEER_GUARD_SOCK_DIR` | `/run/user/<uid>/cc-socks` if it exists, else `$XDG_RUNTIME_DIR/cc-socks` when that is set, else `/run/user/<uid>/cc-socks` | Where Claude Code keeps its per-session sockets. The macOS location is not verified; set this there. |
| `AGENT_TIERS_STATE_DAYS` | `7` | Age in days after which per-session marker files are deleted. |
| `AGENT_TIERS_LEDGER_DAYS` | `14` | Age in days after which authorship and numeric-claim ledger files are deleted. |
| `AGENT_TIERS_SHARE_REMOTE` | `origin` | Remote that `agent-tiers-share` pushes the branch and tag to (same as its `--remote` flag). |
| `AGENT_TIERS_PEER_IDLE_SECS` | `3600` | A SendMessage to another session idle longer than this is denied unless the message carries `WAKE-OK:<why>`, since waking it re-reads its whole context with a cold prompt cache. 1 to 604800, else the default. |
| `AGENT_TIERS_GUARDS_LOG` | `.state/guards.log` in the kit | Where guard decisions are logged. |

A day count that is not a whole number from 1 to 3650 falls back to the default.
